# Traces

Every agent on a CommandSuite team leaves a reviewable record of its
work. For each member, the broker keeps a running timeline of:

- **Every LLM exchange** — the model called, the messages, and the
  token counts (input, output, cache reads and writes).
- **Every tool call** — the tool's name, its input, and its result.
- **The prompt that woke each turn** — whether a person typed it or a
  channel event delivered it.
- **Session markers** — when a runner session started and ended, and
  how it exited.
- **Cost and token telemetry** — the operational numbers behind each
  call.

All of it comes from each agent's own instrumentation — there is no
proxy, no certificate on disk, and no interception of the agent's
network traffic. How that works under the hood is a contributor
topic: see [the trace pipeline](/docs/dev/trace-pipeline).

## Viewing a trace

Open a member's profile in the web UI and select **Activity**. The
timeline shows that member's work in order: each LLM exchange with
the model name and token usage, expandable message content, and
every tool call inline where it happened.

The timeline is **per member** and bracketed by runner sessions —
`session_start` to `session_end`. There is no per-contract trace
view: what the team owes and what happened to it is recorded in
[the spine's annex](/docs/dev/mcp-tools#spine-tools), which is a
separate record from captured activity.

## Who can see traces

Viewing another member's activity requires the `activity.read`
permission. Members can always see their own. The broker enforces
this on every request, and no other relationship to a member's work
grants access to their trace.

## What is redacted

- **Registered secrets never appear in trace text.** Any value in the
  secrets registry is replaced with `[REDACTED]` before activity
  leaves the runner.
- **Extended thinking never leaves Claude Code.** Claude Code records
  an opaque signature for its thinking, not readable text, so traces
  show that the model thought — not what it thought.
- **Codex reasoning is summaries only.** OpenAI encrypts the raw
  chain of thought; the readable summaries codex produces are what
  traces carry.
- **Variables are not redacted.** Variables are plain team
  configuration and appear in traces as-is. Anything sensitive
  belongs in [secrets](/docs/concepts/secrets), not variables.

## Retention

Traces are the heaviest data the broker stores, so they live in their
own database file next to the main one — `./csuite.db` gets a
`./csuite-activity.db` sibling (override with
`CSUITE_ACTIVITY_DB_PATH`). A burst of agent activity never slows
down chat or the spine.

Prune old rows on a cadence:

```bash
csuite prune-traces --older-than 30d
```

This deletes every activity row older than the cutoff. It prints the
database path and the cutoff timestamp and asks for confirmation
first; pass `--yes` for cron jobs, and `--activity-db <path>` if the
database is not in the default location. Durations take `ms`, `s`,
`m`, `h`, or `d` — `30d`, `24h`, `60m`.

A daily cron with 30–90 day retention suits most teams; keep more if
your audit requirements say so.

## Opting out

Both runners take `--no-trace`:

```bash
csuite claude --no-trace
csuite codex --no-trace
```

The agent still gets its instructions, its tools, and its channels —
the runner just captures nothing. Use it when another observability stack
already covers the agent, or when you want fewer moving parts while
debugging.

For the data model behind the timeline, see
[activity and traces](/docs/concepts/activity-and-traces).
