# REST API

This page is for people building on the broker's HTTP API directly —
SDK consumers, integrations, and contributors to the server itself.

The broker exposes a single HTTP API consumed by both the SDK
client (machine plane, bearer auth) and the web UI (human plane,
session cookie). All paths and types are defined by
`csuite-sdk` — `csuite-sdk/protocol` for path constants,
`csuite-sdk/schemas` for zod request / response shapes.

Every request carries `X-CSUITE-Protocol: 2` and is validated
against the schema. Schema mismatches return 400 with a JSON
error body. Long-lived runners additionally send
`X-CSUITE-Runner-Version: <version>` (the
`RUNNER_VERSION_HEADER` constant in `packages/sdk/src/protocol.ts`)
so the broker knows which client version it is composing for — see
`GET /instructions` below.

## Auth

Three planes, all resolving to the same loaded member:

| Plane | Header | Source |
|---|---|---|
| Bearer | `Authorization: Bearer csuite_<base64url>` | `~/.config/csuite/auth.json` (CLI) or directly issued tokens |
| Session | `Cookie: csuite_session=<id>` | After successful TOTP login |
| JWT (federation, optional) | `Authorization: Bearer <jwt>` | A platform that's been bound via the platform-connect flow |

In the tables below:

| Auth label | Means |
|---|---|
| **dual** | Bearer OR session cookie |
| **bearer** | Bearer only |
| **session** | Session cookie only |
| **manage** | Requires `members.manage` permission |
| **manage OR self** | `members.manage`, OR `caller.name === target.name` |
| **self** | Caller must be the target member |
| **read OR self** | `activity.read`, OR caller is target |
| **none** | Unauthenticated (used for health, enrollment, lookups) |

## Health

### `GET /healthz`

| | |
|---|---|
| **Auth** | none |
| **Body** | — |
| **Returns** | `200 { status: "ok", version: <semver>, capabilities: { rawBodyAck: true } }` |

Liveness probe. Cheap; always responds 200 if the process is up.
`capabilities` advertises optional server features to runners:
`rawBodyAck: true` means the OTLP logs ingest supports the
`X-CSuite-Raw-Bodies` capture acknowledgement (see
[OTLP telemetry ingest](#otlp-telemetry-ingest)).

## Instructions

### `GET /instructions`

| | |
|---|---|
| **Auth** | dual |
| **Body** | — |
| **Request headers** | `X-CSUITE-Runner-Version: <version>` (optional) |
| **Returns** | `InstructionsResponse` |

The member's composed instruction packet. Returns the caller's full
member record (name, role, instructions, permissions) plus the team
(name, context, permissionPresets), the public projection
of every teammate, the caller's currently-open objectives, the
external tools resolved for them (`toolSources`), and the team's
process document (`processDocument` — `null` when none is set,
absent on brokers that predate the field).

The response also names what was composed, by content hash:

- `blocks` — one `{ kind, sha256 }` descriptor per operator-authored
  instruction block actually present in this packet. Kinds are
  `team_context`, `role_description`, `personal_instructions`, and
  `process_document` (the wire strings are pinned). Empty blocks are
  omitted rather than descriptor'd.
- `composedSha256` — sha256 of the **canonical** composition: the
  composed `instructions` prose with the transient broker/runner
  version line normalized out, plus the process-document text. The
  broker records this hash as "issued" to the member on every fetch
  and compares it against the current composition to decide
  restart-pending (`GET /roster` below). Two fetches that differ
  only in reported runner version share a hash by construction — a
  runner upgrade never reads as an instruction edit.

`X-CSUITE-Runner-Version` is how a long-lived runner reports its
loaded version. The value must match
`^[0-9A-Za-z][0-9A-Za-z.+-]{0,63}$` (rejected values are logged and
ignored). The broker folds both versions into the first line of the
composed `instructions` prose —
`<team> CommandSuite/csuite: broker=<v> runner=<v>` — so every
captured trace records which broker and runner composed the
session's context (values longer than 12 characters are shortened
for display). The SDK sends it via
`client.instructions({ runnerVersion })`.

The runner caches this at startup and uses it for the session — the
composed `instructions` prose is pinned into the agent's system
prompt, `openObjectives` seeds the runner's `context_refresh` push,
and `permissions` decides which permission-gated tools appear in
`tools/list`. It refetches mid-session in exactly two cases: a
`tool_source` registry event (to recompute the external toolbox) and
the drain-and-restart cycle an instruction edit triggers (below).

## Roster

### `GET /roster`

| | |
|---|---|
| **Auth** | dual |
| **Returns** | `RosterResponse` — `{ teammates: Teammate[], connected: Presence[], restartPending: string[], activityWindowMs }` |

Public projection of teammates plus a parallel list of live
presence (connection count, last-seen, busy flag). For the
presence model see [presence](/docs/concepts/presence).

`restartPending` lists members whose current composed instructions
differ from what their live session was issued — their runner
restarts the agent at its next idle boundary to pick the edit up.
The tracking is in-memory and deliberately forgetful: a member whose
issued hash is unknown (the broker restarted since their
`GET /instructions` fetch) is NOT listed — unknown is not pending.

## Push / subscribe / history

### `POST /push`

| | |
|---|---|
| **Auth** | dual |
| **Body** | `PushPayload` — `{ to?, title?, body, level?, data?, attachments? }` |
| **Returns** | `PushResult` — `{ delivery: { live, targets }, message: Message }` |

Send a message. `to: <name>` is a DM; `to: null` (or omitted)
plus `data.thread = 'chan:<id>'` is a channel post; otherwise
it's a broadcast to general. The broker stamps `from` from the
authenticated member; payloads cannot override.

### `GET /subscribe?name=<self>` (WebSocket)

| | |
|---|---|
| **Auth** | dual |
| **Upgrade** | WebSocket — each broker push targeting the member arrives as one JSON text frame (`ws.send(JSON.stringify(message))`), shape `Message` |

Subscribe to messages addressed to `self` (the authenticated
caller's name). This is a WebSocket upgrade, not SSE — the SDK's
`client.subscribe(name)` wraps the socket in an async iterable. A
missing `name` or an identity mismatch is rejected by pre-upgrade
middleware with a plain HTTP 400/403 (the broker enforces
`name === caller.name`), so a bad request never half-upgrades.
Multiple concurrent subscribers per member are supported (the
`Presence.connected` count reflects that). On server shutdown every
live socket is closed with code `1001`.

Two side effects fire when the subscriber is a runner (opaque
bearer auth, i.e. `tokenId !== null` — never web-UI sessions or
federated JWTs): the broker DMs a session-online notice from
`csuite` summarizing the member's open plate, and external
notifications queued with `if_offline: queue` are flushed.

### `GET /history?with=<name>&channel=<id-or-slug>&limit=<N>&before=<ts>`

| | |
|---|---|
| **Auth** | dual |
| **Returns** | `HistoryResponse` — `{ messages: Message[] }` |

Newest-first message history. Pass exactly one of `with` (DM
thread with the named teammate) or `channel` (slug or id — the
caller must be a member of the channel). Omitting both returns
general channel scrollback. `limit` defaults to 100, max 1000
(the MCP `recent` tool applies its own tighter 50/500 bounds
client-side). `before` is an epoch-ms cursor for paging.

## Sessions and TOTP

### `POST /session/totp`

| | |
|---|---|
| **Auth** | none |
| **Body** | `TotpLoginRequest` — `{ code: "<6 digits>", member?: "<name>" }` |
| **Returns** | `200 SessionResponse` + `Set-Cookie: csuite_session=<id>` |

When `member` is set, the server verifies against just that
member. When omitted, the server iterates enrolled members
looking for a match (codeless login). Rate-limited: 5 failures /
15min per member, 10 failures / 15min global.

On success the session cookie is `httpOnly`, `Secure` over HTTPS,
`SameSite=Strict`, 7-day sliding TTL — every authenticated request
bumps `last_seen` and re-stamps the expiry.

### `GET /session`

| | |
|---|---|
| **Auth** | dual |
| **Returns** | `SessionResponse` — `{ member, role, permissions, expiresAt }` |

Current session info. Useful for the web UI to bootstrap.

### `POST /session/logout`

| | |
|---|---|
| **Auth** | dual |
| **Returns** | `204` + cleared cookie |

## Members

### `GET /members`

| | |
|---|---|
| **Auth** | dual |
| **Returns** | `ListMembersResponse` — `{ members: Member[] }` |

Callers with `members.manage` see the full list including private
`instructions`. Other callers see the public projection — same as
`roster.teammates`.

### `POST /members`

| | |
|---|---|
| **Auth** | manage |
| **Body** | `CreateMemberRequest` — `{ name, role, instructions?, permissions: string[] }` |
| **Returns** | `CreateMemberResponse` — `{ member: Teammate, token: <plaintext> }` |

The `token` plaintext is returned exactly once; only its SHA-256
hash is persisted. `permissions` accepts preset names or leaf
permissions in any mix; the server resolves at create time.

### `PATCH /members/:name`

| | |
|---|---|
| **Auth** | manage |
| **Body** | `UpdateMemberRequest` — `{ role?, instructions?, permissions? }` |
| **Returns** | `Member` (plus `warning`, mirrored in an `X-CSuite-Warning` header, when the new role description or instructions contain a registered secret value) |

Patches any subset of fields. Enforces "at least one
`members.manage` member must remain" — rejects with 400 if the
update would remove `members.manage` from its sole holder.

Role and instructions edits fan out one `kind: 'instructions'`
channel event to every member whose composed instruction text
changed — a role edit also reaches teammates whose roster line
moved, since that line is composed into their prose. Each affected
runner restarts its agent at the next idle boundary under the new
text, resuming the same conversation; `GET /roster` lists those
members in `restartPending` until it does. Permission-only patches
never touch the prose and fan nothing out.

### `DELETE /members/:name`

| | |
|---|---|
| **Auth** | manage |
| **Returns** | `204` |

Same capability-holder invariant as `PATCH`. Tokens for the deleted
member are invalidated.

### `POST /members/:name/rotate-token`

| | |
|---|---|
| **Auth** | manage OR self |
| **Returns** | `RotateTokenResponse` — `{ token: <plaintext>, tokenInfo? }` |

Revokes every active token for the member and mints a fresh one.
Plaintext returned once; metadata in `tokenInfo` lets the caller
display label / id without a follow-up list.

### `GET /members/:name/tokens`

| | |
|---|---|
| **Auth** | manage OR self |
| **Returns** | `ListTokensResponse` — `{ tokens: TokenInfo[] }` |

List active bearer tokens with metadata (label, origin,
createdAt, lastUsedAt, expiresAt, createdBy). Plaintext is never
exposed by this shape.

### `DELETE /members/:name/tokens/:id`

| | |
|---|---|
| **Auth** | manage OR self |
| **Returns** | `204` |

Revoke a specific token by uuid. Revoking the token currently
authenticating the request is allowed.

### `POST /members/:name/enroll-totp`

| | |
|---|---|
| **Auth** | manage OR self |
| **Returns** | `EnrollTotpResponse` — `{ totpSecret, totpUri }` |

Mints (or rotates) a TOTP secret. Re-enrolling invalidates any
authenticator currently bound. Confirmation is enforced
client-side (CLI / web UI prompts for the 6-digit code from the
new authenticator before persisting).

### `POST /members/:name/activity`

| | |
|---|---|
| **Auth** | self only |
| **Body** | `UploadActivityRequest` — `{ events: ActivityEvent[] }` (1–500) |
| **Returns** | `UploadActivityResponse` — `{ accepted: <count> }` |

Runner-side activity upload. The server stamps each event with a
row id and broadcasts to live `/activity/stream` subscribers.

### `GET /members/:name/activity?from=<ts>&to=<ts>&kind=<k|k[]>&limit=<n>&cursor_ts=<ts>&cursor_id=<id>`

| | |
|---|---|
| **Auth** | read OR self |
| **Returns** | `ListActivityResponse` — `{ activity: ActivityRow[] }` |

Range query. Returns newest-first up to 1000 rows. `kind` filter
accepts a single value or repeated params, OR-combined
(`session_start | session_end | objective_open | objective_close |
llm_exchange | tool_action | user_prompt`). `cursor_ts` +
`cursor_id` form a composite paging cursor (both or neither —
"rows strictly before this (ts, id)"), which stays stable when many
rows share a timestamp.

The TracePanel uses
`from=<objective.createdAt>&to=<objective.completedAt>&kind=llm_exchange`
to render per-objective traces.

### `GET /members/:name/activity/stream` (WebSocket)

| | |
|---|---|
| **Auth** | read OR self |
| **Upgrade** | WebSocket — each row appended to the member's activity store arrives as one JSON text frame, shape `ActivityRow` |

Live tail of the activity stream — a WebSocket upgrade, not SSE.
Name and permission are validated by pre-upgrade middleware so
rejection is a proper HTTP 400/403 rather than a failed handshake;
on server shutdown the socket closes with code `1001`. Used by the
TracePanel for in-flight objectives where new events keep arriving.

### `GET /members/:name/genai?from=<ts>&to=<ts>&limit=<n>&view=summary`

| | |
|---|---|
| **Auth** | read OR self |
| **Returns** | `ListGenaiResponse` — `{ inferences: GenAiInferenceRecord[] }` (or `GenAiInferenceSummary[]` with `view=summary`) |

The full-fidelity request layer behind the trace viewer: stored
GenAI inference records carrying `systemInstructions` and the
complete `inputMessages` context, captured from the agent's own
body export (Claude Code OTLP bodies, codex rollout bundles).
Oldest-first within the `from`/`to` bounds (applied to capture
time `ts`). Server-internal raw-body pointers never cross the wire.

`view=summary` serves the light call-ledger projection — every
field EXCEPT the three content arrays (`systemInstructions`,
`inputMessages`, `outputMessages`). Cheap enough for the activity
timeline to hydrate a whole feed window; full bodies then load one
call at a time via the by-id route below.

Coverage is best-effort — rows exist only for calls whose bodies
the agent's instrumentation exported — so trace surfaces JOIN
these onto the always-present `llm_exchange` activity markers
(exactly by the shared API `responseId` for Claude rows, else by
interval containment in the turn's `[startedAt, endedAt]` window,
gated by `querySource` class) rather than reading this endpoint
alone. Records that join no marker (subagent calls, web-search
sidecars, away summaries) render as their own attributed rows. The
POST verb on the same path is the codex upload (self-only).

### `GET /members/:name/genai/:id`

| | |
|---|---|
| **Auth** | read OR self |
| **Returns** | `GetGenaiInferenceResponse` — `{ inference: GenAiInferenceRecord }` |

One full record by server-assigned id — the heavy-body counterpart
of a `view=summary` row, fetched by the timeline when a viewer
expands a call. An id that doesn't exist or belongs to a different
member is a 404 (indistinguishable, so ids don't leak ownership).

### `GET /members/:name/genai/:id/raw?kind=request|response`

| | |
|---|---|
| **Auth** | read OR self |
| **Returns** | `application/octet-stream` — the stored bytes, with `X-CSuite-Body-Sha256` |

The verbatim source the parsed record was mapped from, byte-exact
with respect to what was stored after redaction.

Addressed through the inference rather than by content hash on
purpose. The blob store is deduplicated into one global content
space, so byte-identical bodies from two members are a single row;
a hash-addressed read would cross member boundaries as a matter of
routine rather than as an edge case. Routing through the record
keeps the ownership check in front of the bytes.

Three absences are distinguished, because they are different facts
about capture coverage: **404** for no such inference, **404** with
a `no raw <kind> captured` message for a record whose raw side was
never captured, and **410** for a record that outlived its bytes
(retention collects a blob once nothing references it; a blob whose
bytes fail their own hash check on read reports the same way rather
than serving corrupt content).

### `GET /members/:name/telemetry?signal=<log|metric>&event=<name>&from=<ts>&to=<ts>&limit=<n>&cursor_ts=<ts>&cursor_id=<id>`

| | |
|---|---|
| **Auth** | read OR self |
| **Returns** | `ListTelemetryResponse` — `{ telemetry: TelemetryRecordRow[] }` |

The operational accounting behind a trace: one row per OTLP log
record or metric data point the member's agent exported — cost,
tokens, durations, errors, lifecycle. Oldest-first within the
window, paged with the same composite cursor as the activity and
gen_ai endpoints.

Deliberately unfiltered at ingest: there is no allowlist on record
or metric names, so a newer agent's signals appear here without a
broker change. `attributes`, `resource`, `scope` and `payload` are
passthrough objects for the same reason.

This is separate from `GET /members/:name/genai` because the two
answer different questions — this is the accounting, that is the
content.

## Team

Team-level config is the name and shared context. Reads are open to every
authenticated member; mutations require `team.manage`.

A `context` edit is instruction-bearing: it fans out one
`kind: 'instructions'` channel event to every member whose composed
instruction text changed, each affected runner restarts its agent at
the next idle boundary under the new text, and `GET /roster` lists
those members in `restartPending` until it does. A `name`-only patch
fans out the same way — the team name is the first line of every
member's composed prose, so it moves every composition.

### `GET /team`

| | |
|---|---|
| **Auth** | dual |
| **Returns** | `{ team: Team }` — `{ name, context }` plus a deprecated empty compatibility field on current servers |

### `PATCH /team`

| | |
|---|---|
| **Auth** | dual; `team.manage` |
| **Body** | `{ name?, context? }` (at least one) |
| **Returns** | `{ team: Team }` |

If the new `context` contains a registered secret value the update
still lands, but the response carries a `warning` field (mirrored
in an `X-CSuite-Warning` header) — the string will appear verbatim
in captured traces.

## Objectives

### `GET /objectives?assignee=<name>&related=<name>&status=<s>`

| | |
|---|---|
| **Auth** | dual |
| **Returns** | `ListObjectivesResponse` — `{ objectives: Objective[] }` |

Callers **without** `objectives.create` are scoped to their own
relationship union — objectives they are assigned, originated, or
watch — and may only pass their own name in `assignee` / `related`
(403 otherwise). Callers **with** `objectives.create` get the
team-wide list; `related=<name>` narrows it to one member's
relationship union, `assignee=<name>` to one member's plate. The
MCP `objectives_list` tool sits on top of this route.

### `POST /objectives`

| | |
|---|---|
| **Auth** | dual; requires `objectives.create` |
| **Body** | `CreateObjectiveRequest` — `{ title, outcome, assignee, body?, watchers?, attachments? }` |
| **Returns** | `Objective` |

Creates the objective and appends an `assigned` audit event in
the same transaction. Originator is stamped from the caller. If
`watchers` are supplied, they're de-duped and validated; each
must resolve to a known member. `attachments` validate that the
caller has read access to each path.

### `GET /objectives/:id`

| | |
|---|---|
| **Auth** | dual; thread participant (assignee, originator, watcher) OR `objectives.create` |
| **Returns** | `GetObjectiveResponse` — `{ objective: Objective, events: ObjectiveEvent[] }` |

Full state plus the append-only event log.

### `PATCH /objectives/:id`

| | |
|---|---|
| **Auth** | dual; gated per field group — see below |
| **Body** | `UpdateObjectiveRequest` — `{ status?: 'active'\|'blocked', blockReason?, assignee?, note?, addWatchers?, removeWatchers? }` (at least one field) |
| **Returns** | `Objective` |

One mutation surface, gated per field group: `status`/`blockReason`
require the assignee or `objectives.cancel`; `assignee` (a
reassignment — the previous assignee is promoted to watcher, both
parties notified, `note` carries handover context) requires
`objectives.reassign`; watcher changes require the originator or
`objectives.watch`. A payload touching several groups must satisfy
every gate it touches, and all gates are checked before any change
applies. `blockReason` is optional; setting `assignee` to the current
assignee is an idempotent no-op. Use `complete` / `cancel` for
terminal states.

### `POST /objectives/:id/complete`

| | |
|---|---|
| **Auth** | dual; **assignee only** |
| **Body** | `CompleteObjectiveRequest` — `{ result: <required string> }` |
| **Returns** | `Objective` |

Terminal transition to `done`. The result string goes into the
audit log and is the "what was actually delivered" summary.

### `POST /objectives/:id/cancel`

| | |
|---|---|
| **Auth** | dual; `objectives.cancel` OR originator |
| **Body** | `CancelObjectiveRequest` — `{ reason? }` |
| **Returns** | `Objective` |

Terminal transition to `cancelled`.

### `POST /objectives/:id/discuss`

| | |
|---|---|
| **Auth** | dual; thread member only |
| **Body** | `DiscussObjectiveRequest` — `{ body, title?, attachments? }` |
| **Returns** | `Message` (the underlying push) |

Posts into the `obj:<id>` thread. Members include originator,
assignee, watchers, plus members with `members.manage` (implicit).

## Process document

The team's process as one authored document. Reads are open to every
member — what binds you is not privileged information. Writes require
`process.manage`, a dedicated leaf: under this design the permission is
the entire authority.

The current document is also served on `GET /instructions` as
`processDocument`, which is how it reaches a member's fixed context.
These endpoints exist for what injection does not carry.

### `GET /process-document`

| | |
|---|---|
| **Auth** | dual |
| **Returns** | `{ document: ProcessDocument \| null }` |

`null` rather than 404 when none has been set. A team that has never
written one is a real state, not a missing resource, and a 404 would
make the caller guess which it was.

### `GET /process-document/history`

| | |
|---|---|
| **Auth** | dual |
| **Returns** | `{ edits: ProcessDocumentEdit[] }`, oldest first |

Retrieved, never resident. Each edit carries the author, reason,
`disposition` and the **full prior text**, so the diff is derived from
two stored strings rather than cached — a cached diff is a second copy
that can drift from the text it describes.

Version 1 is the creation and carries no prior text.

### `PUT /process-document`

| | |
|---|---|
| **Auth** | dual; requires `process.manage` |
| **Body** | `EditProcessDocumentRequest` — `{ text, reason, disposition }` |
| **Returns** | `{ document, edit }` — **201** on create, **200** on edit |

Create and edit are one path. The first authorised write produces
version 1 with a real author and reason; history begins there rather
than at a migration that would have to invent the document's text. It
also means the invariant validator runs on the real endpoint for both.

`text` replaces the document entirely. The document move and the
history append are one transaction — a document whose text moved
without its prior version recorded is unrecoverable, and worse than
immutability.

`text` is capped at 16384 characters. That is a real ceiling with a
stated basis: the document is resident in every member's context in
every session, so its length is a recurring cost paid by everyone.

Like every instruction-bearing edit, a write fans out one
`kind: 'instructions'` channel event to each member whose composed
context changed. Their runners restart the agent at the next idle
boundary under the new text, and `GET /roster` lists those members
in `restartPending` until they do.

## Tool sources

Registry of platform-defined external tools — see
[tool sources](/docs/concepts/tool-sources) for the model. All
endpoints are dual-auth. Mutations require `tools.manage`; invoke
requires the caller be bound to the source (or the source be
`allMembers`). Credentials are write-only.

| Verb + path | Gate | Notes |
|---|---|---|
| `GET /tool-sources` | any member | Per-viewer summaries (`bound`, `toolCount`, `hasCredential`). |
| `POST /tool-sources` | `tools.manage` | Body: `CreateToolSourceRequest` (`slug`, `kind: custom\|mcp`, `config.url` for mcp). 201 + `ToolSource`. |
| `GET /tool-sources/:slug` | any member | Detail + tool defs; `boundMembers` only for `tools.manage` viewers. |
| `PATCH /tool-sources/:slug` | `tools.manage` | `displayName` / `config` / `enabled` / `allMembers`. Slug is immutable. |
| `DELETE /tool-sources/:slug` | `tools.manage` | Cascades bindings, credential, tool defs, MCP cache. |
| `PUT /tool-sources/:slug/credential` | `tools.manage` | `{ kind: bearer\|header, headerName?, secret }`. KEK-encrypted; never returned. 503 without an active KEK. |
| `DELETE /tool-sources/:slug/credential` | `tools.manage` | — |
| `POST /tool-sources/:slug/bindings` | `tools.manage` | `{ member }`. |
| `DELETE /tool-sources/:slug/bindings/:name` | `tools.manage` | Removed member is notified. |
| `PUT /tool-sources/:slug/tools/:name` | `tools.manage` | kind=custom: `{ description, inputSchema, binding }`. Binding validated at save (static origin, header guards). |
| `DELETE /tool-sources/:slug/tools/:name` | `tools.manage` | kind=custom. |
| `POST /tool-sources/:slug/refresh` | `tools.manage` | kind=mcp: synchronous upstream discovery. `{ tools, changed }`; 502 when unreachable. |
| `POST /tool-sources/:slug/tools/:name/invoke` | bound member | `{ args? }` (≤ 1 MiB). Returns an MCP `CallToolResult`; tool failures are `200 + isError: true`. 403 unbound → 409 disabled → 404 unknown tool. Appends a `tool_action` audit event. |

Registry changes fan out as `data.kind = 'tool_source'` channel
events (thread `tool:<slug>`) to the source's visible members plus
`tools.manage` holders — runners refetch their instructions and emit
`tools/list_changed` when their resolved set changes.

## Secrets

Broker-held environment secrets — see
[secrets](/docs/concepts/secrets) for the model. All endpoints are
dual-auth. Mutations require `secrets.manage`; values are write-only
(never returned; summaries expose `hasValue` only).

| Verb + path | Gate | Notes |
|---|---|---|
| `GET /secrets` | any member | Per-viewer summaries (`bound`, `hasValue`). |
| `POST /secrets` | `secrets.manage` | Body: `CreateSecretRequest` (`slug`, `envName`, `description?`, `allMembers?`). 400 on malformed/reserved `envName`; 409 on taken slug or envName. 201 + `Secret`. |
| `GET /secrets/resolve` | any member | The runner's read path: `{ env, secretEnvNames }` for the **calling member only**, keyed by envName. `env` merges decrypted secrets with the member's [variables](#variables); `secretEnvNames` lists which keys came from the secrets store (only those are registered with the trace redactor — absent on older brokers, in which case treat every key as secret). Skips valueless secrets; 409 if the member resolves one env name from both stores; 503 without an active KEK. |
| `GET /secrets/:slug` | any member | Detail; `boundMembers` only for `secrets.manage` viewers. |
| `PATCH /secrets/:slug` | `secrets.manage` | `envName` / `description` / `enabled` / `allMembers`. Slug is immutable. |
| `DELETE /secrets/:slug` | `secrets.manage` | Cascades bindings and the stored value. |
| `PUT /secrets/:slug/value` | `secrets.manage` | `{ value }` (≤ 32 KiB). KEK-encrypted; never returned. 503 without an active KEK. |
| `DELETE /secrets/:slug/value` | `secrets.manage` | — |
| `POST /secrets/:slug/bindings` | `secrets.manage` | `{ member }`. |
| `DELETE /secrets/:slug/bindings/:name` | `secrets.manage` | Removed member is notified. |

Registry changes fan out as `data.kind = 'secret'` channel events
(thread `secret:<slug>`) to the delivery set plus `secrets.manage`
holders. Events never carry the value. Delivery is spawn-time only —
changes apply on each member's next runner start.

## Variables

Broker-held runner environment variables that are **not** secrets —
see [variables](/docs/concepts/variables) for the model. Same
lifecycle and route shapes as `/secrets/*`, and the same
`secrets.manage` gate on mutations. The differences: a variable's
value is **readable** by a `secrets.manage` holder (summaries carry
`value`), it is never registered with the trace redactor, and it is
never KEK-encrypted. Secrets and variables share one per-member
environment namespace — creating or binding a collision fails with
409 (`env_taken`), and `GET /secrets/resolve` merges both stores
into the env map the runner injects.

| Verb + path | Gate | Notes |
|---|---|---|
| `GET /variables` | any member | Per-viewer summaries; `value` included for `secrets.manage` viewers. |
| `POST /variables` | `secrets.manage` | Body: `CreateVariableRequest` (`slug`, `envName`, `description?`, `allMembers?`, `enabled?`). Same slug/envName grammar as secrets. 201 + `{ variable }`. |
| `GET /variables/:slug` | any member | Detail; `value` and `boundMembers` only for `secrets.manage` viewers. |
| `PATCH /variables/:slug` | `secrets.manage` | `envName` / `description` / `enabled` / `allMembers`. Slug is immutable. Returns `{ variable }`. |
| `DELETE /variables/:slug` | `secrets.manage` | Cascades the value and bindings. Returns `{ ok: true }`. |
| `PUT /variables/:slug/value` | `secrets.manage` | `{ value }`. Stored readable; **never** registered with the trace redactor — not a place for credentials. Returns `{ ok: true }`. |
| `DELETE /variables/:slug/value` | `secrets.manage` | Returns `{ ok: true }`. |
| `POST /variables/:slug/bindings` | `secrets.manage` | `{ member }`. 409 `env_taken` when the member already resolves this envName from a secret or another variable. Returns `{ ok, boundMembers }`. |
| `DELETE /variables/:slug/bindings/:name` | `secrets.manage` | Returns `{ ok, boundMembers }`. |

Registry changes fan out as `data.kind = 'variable'` channel events
(thread `variable:<slug>`) to the delivery set plus `secrets.manage`
holders. Delivery is spawn-time only — changes apply on each
member's next runner start.

## External Notifications

Inbound webhooks / API calls routed to members and channels as
ambient input — see
[external notifications](/docs/concepts/external-notifications) for
the model. Management endpoints are dual-auth; mutations require
`notifications.manage`. Signing secrets are write-only (never
returned; summaries expose `hasSecret` only).

| Verb + path | Gate | Notes |
|---|---|---|
| `GET /notifications/endpoints` | any member | `notifications.manage` sees all; others see endpoints targeting them. |
| `POST /notifications/endpoints` | `notifications.manage` | Body: `CreateNotificationEndpointRequest` (`slug`, `targets`, `auth?`, `authProfile?`, `filters?`, `template?`, `policy?`, `dedupeHeader?`, …). Channel targets accept slug or id (stored as id). 409 on taken slug. 201 + `NotificationEndpoint`. |
| `GET /notifications/endpoints/:slug` | manage OR targeted | Detail + `hasSecret`. |
| `PATCH /notifications/endpoints/:slug` | `notifications.manage` | Any mutable subset. Slug is immutable (the ingress URL and `hook:<slug>` identity ride on it). |
| `DELETE /notifications/endpoints/:slug` | `notifications.manage` | Cascades delivery receipts + queued deliveries. |
| `PUT /notifications/endpoints/:slug/secret` | `notifications.manage` | `{ secret }` (≤ 4 KiB). KEK-encrypted; never returned. 503 without an active KEK. |
| `DELETE /notifications/endpoints/:slug/secret` | `notifications.manage` | The endpoint then rejects everything (fail closed). |
| `GET /notifications/endpoints/:slug/deliveries` | `notifications.manage` | Receipts, newest first. `limit` ≤ 500, `before` epoch-ms cursor. |
| `GET /notifications/profiles` | `notifications.manage` | Summaries carry `hasSecret` + `endpointCount`. |
| `POST /notifications/profiles` | `notifications.manage` | `CreateNotificationProfileRequest` (`slug`, `auth`). |
| `PATCH /notifications/profiles/:slug` | `notifications.manage` | `description` / `auth`. |
| `DELETE /notifications/profiles/:slug` | `notifications.manage` | 409 while any endpoint references it. |
| `PUT /notifications/profiles/:slug/secret` | `notifications.manage` | The shared-secret rotation point — one write re-keys every referencing endpoint. |
| `DELETE /notifications/profiles/:slug/secret` | `notifications.manage` | — |
| `POST /notifications/deliveries/:id/replay` | `notifications.manage` | Re-runs the stored raw body through the pipeline (verify/dedupe/rate-limit skipped; filters/template/policy apply). Returns the fresh receipt. |

### `POST /hooks/:slug`

| | |
|---|---|
| **Auth** | none at the middleware layer — verified per-endpoint (HMAC-SHA256 over the raw body, or shared-secret header) against the KEK-held secret |
| **Body** | the sender's raw payload (≤ 256 KiB) |
| **Query** | `if_offline=drop\|queue`, `if_busy=now\|wait`, `level=<LogLevel>` — per-delivery policy overrides |
| **Returns** | `202 { id, status }` — also for `duplicate` / `filtered` / `dropped`; `401` (detail-free) on verification failure; `404` unknown, `409` disabled, `413` oversized, `429` + `Retry-After` on the per-endpoint rate limit (120/min) |

Every request that clears the rate limit lands a delivery receipt,
including rejected ones (the failure reason is on the receipt, not
the wire). Registry changes fan out as
`data.kind = 'notification_endpoint'` events (thread `hook:<slug>`)
to direct member targets plus `notifications.manage` holders.

## OTLP telemetry ingest

Agents post their own OpenTelemetry export here — this is how
Claude Code's OTLP logs and metrics reach the broker. Standard
bearer auth (the OTEL exporter's `Bearer%20` header form is
normalized by the auth middleware). Every record is persisted
losslessly, known or unknown name — dashboards and analytics are
downstream queries, not ingest-time allowlists.

### `POST /otlp/v1/logs`

| | |
|---|---|
| **Auth** | bearer |
| **Body** | OTLP/HTTP-JSON `ExportLogsServiceRequest` |
| **Request headers** | `X-CSuite-Raw-Bodies: <n>` (optional, runner relay only) |
| **Returns** | `200 { partialSuccess: {} }` — plus `csuite: { rawBodiesCaptured }` when the header was sent |

Log records land in the telemetry store. The four gen_ai api-body
record names are additionally routed through the member's GenAI
correlator into full-context inference records; the two raw-body
records (`api_request_body` / `api_response_body`) go to the gen_ai
layer only, while `api_request` / `api_error` stay in both sinks
(they carry cost/token/duration accounting). Native exporters
always receive the OTLP success shape — parse and storage failures
are logged, never surfaced as retryable errors. The
`X-CSuite-Raw-Bodies` extension is the capture acknowledgement the
runner's local relay uses: the response reports how many raw-body
ledger rows this ingest appended, so the runner deletes spool files
only after durable capture (advertised by `GET /healthz` as
`capabilities.rawBodyAck`).

### `POST /otlp/v1/metrics`

| | |
|---|---|
| **Auth** | bearer |
| **Body** | OTLP/HTTP-JSON `ExportMetricsServiceRequest` |
| **Returns** | `200 { partialSuccess: {} }` |

Metrics land in the telemetry store, attributed to the posting
member.

## Presence

### `POST /presence/activity`

| | |
|---|---|
| **Auth** | bearer |
| **Body** | `ActivityReport` — `{ state: ActivityState }` where `ActivityState` is `idle` / `working` / `blocked` |
| **Returns** | `204` |

Runner-only. Reports the agent's live 3-state activity to the
broker on every transition. The server applies a 30s TTL — a
non-idle (`working` / `blocked`) report resolves back to `idle` if
no heartbeat refreshes it. The runner re-posts the current state
every 10s while non-idle, and posts `{ state: "idle" }` once when
the turn ends. `busy` is an optional back-compat mirror the server
derives from `state` when omitted (`busy === true` iff
`state === "working"`).

## Error shapes

All non-2xx responses return JSON:

```json
{ "error": "<short code>", "message": "<human description>" }
```

Common error codes:

| Code | Meaning |
|---|---|
| `bad_request` | Schema validation failed |
| `unauthenticated` | No valid auth on the request |
| `forbidden` | Auth resolved but lacks the required permission |
| `not_found` | Resource doesn't exist |
| `conflict` | Slug / name collision, or invariant would be violated |
| `gone` | Resource is archived (channel, completed objective with destructive intent) |
| `rate_limited` | TOTP / enrollment rate limit hit; check `Retry-After` |
| `payload_too_large` | Body exceeded the per-route cap |

Validation errors include a `details` field with the zod issue
list when applicable.
