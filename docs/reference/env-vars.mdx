# Environment variables

Every variable here is one **you** set. Flags win over environment
variables; environment variables win over saved config.

## CLI

Read by every `csuite` command that talks to a broker.

| Name | Default | Purpose |
|---|---|---|
| `CSUITE_URL` | `http://127.0.0.1:8717` | Broker base URL. Overridden by `--url`. |
| `CSUITE_TOKEN` | (none) | Bearer token. Overridden by `--token`; falls back to the saved auth store when unset. |
| `CSUITE_AUTH_CONFIG_PATH` | platform-specific (below) | Override the auth store path. |
| `CLAUDE_PATH` | the bundled Claude Code | Point `csuite claude` at a specific Claude Code executable. Unset means the build that ships with the CLI. |
| `CODEX_PATH` | `codex` on `$PATH` | Point `csuite codex` at a specific codex binary. |

Auth store default location:

| OS | Path |
|---|---|
| Linux/BSD | `$XDG_CONFIG_HOME/csuite/auth.json` (default `~/.config/csuite/auth.json`) |
| macOS | `~/Library/Application Support/csuite/auth.json` |
| Windows | `%APPDATA%\csuite\auth.json` |

## Broker

Read by `csuite serve` (and `csuite setup` / `csuite prune-traces`
where noted).

| Name | Default | Purpose |
|---|---|---|
| `CSUITE_CONFIG_PATH` | `./csuite.json` if present, else `./csuite/csuite.json` | Server config file path. Also read by `csuite setup`. |
| `CSUITE_PORT` | `8717` | Listen port. |
| `CSUITE_HOST` | `127.0.0.1` | Bind address. |
| `CSUITE_DB_PATH` | `csuite.db` next to the config | Main SQLite database — team, members, tokens, messages, objectives. |
| `CSUITE_ACTIVITY_DB_PATH` | `<dbPath basename>-activity.db` | Trace database. Also read by `csuite prune-traces`. Point it at a separate disk if trace volume is heavy. |
| `CSUITE_KEK` | auto-generated key file next to the config | The key that encrypts secrets at rest, as 32 bytes base64. Set it from a secrets manager in production; unset, the broker mints `csuite-kek.bin` alongside the config on first boot. |

## Logging

Read by every csuite process — broker, CLI, and runner alike.

| Name | Default | Purpose |
|---|---|---|
| `CSUITE_LOG_LEVEL` | `info` | Minimum severity emitted: `debug`, `info`, `warn`, or `error`. A value naming no level logs a warning and falls back to `info` rather than failing silently. |

Every process writes the same record — one JSON object per line, on
stderr, so stdout stays clean for startup banners and command output:

```json
{"ts":"2026-08-14T12:00:00.000Z","level":"warn","component":"activity-uploader","msg":"queue full, dropped oldest","dropped":12}
```

`component` names the subsystem, so a shipper can filter by it without
parsing the message. Runner logs go to
`~/.cache/commandsuite/session-<pid>.log` instead of stderr when stderr
is a TTY — otherwise the JSON would corrupt the agent's terminal UI.
Redirect stderr (`2> run.log`, a pipe, CI) and they stay on the stream.
Those files are swept on the next runner start once they are a week
old.

## Values delivered to agents

You don't set the agent's environment directly — the broker does, at
runner start:

- Every [secret](/docs/concepts/secrets) bound to the member arrives
  as its configured environment variable. Secret values are redacted
  from captured traces. `--no-secrets` skips them.
- Every [variable](/docs/concepts/variables) bound to the member
  arrives the same way, but variable values are **not** redacted —
  that's what they're for (git identity, other public values).

The runner also sets internal capture and bridge configuration on the
agent; those are managed for you and documented in
[the trace pipeline](/docs/dev/trace-pipeline).

## System variables csuite respects

| Var | Effect |
|---|---|
| `XDG_CONFIG_HOME` | Linux/BSD auth store location. Defaults to `~/.config`. |
| `XDG_CACHE_HOME` | Linux/BSD cache location (session logs, codex working directories). Defaults to `~/.cache`. |
| `XDG_DATA_HOME` | Linux/BSD data location (codex resume history). Defaults to `~/.local/share`. |
| `APPDATA` | Windows equivalent of `XDG_CONFIG_HOME`. |
| `TMPDIR` | Runner scratch space; checked by `--doctor`. |
| `HOSTNAME` | Default `--label` hint for `csuite connect`. |

## Variables csuite does not read

- `ANTHROPIC_API_KEY` — Claude Code reads it directly; csuite doesn't
  touch it.
- `OPENAI_API_KEY` — codex auth comes from your `codex login`, which
  the runner reuses.
