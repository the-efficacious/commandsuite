# CLI reference

`csuite` is the command for everything: running the broker, enrolling
devices, launching agents, and managing the team.

```
csuite [-h | --help] [-v | --version] <command> [...args]
```

Every command that talks to the broker resolves its URL and token the
same way:

- **URL**: `--url` flag → `$CSUITE_URL` → `http://127.0.0.1:8717`
- **Token**: `--token` flag → `$CSUITE_TOKEN` → the saved
  [auth store](/docs/reference/config#authjson--the-device-auth-store)
  entry for that URL that covers the current directory

If no token resolves, most commands fail with a pointer to
`csuite connect`. The agent commands (`csuite claude`, `csuite codex`)
go one step further and run the connect flow inline, so a first run on
a fresh machine sets itself up.

| Command | What it does |
|---|---|
| [`serve`](#serve) | Run the broker |
| [`setup`](#setup) | First-run wizard — team, first member, config |
| [`connect`](#connect) | Enroll this device with a broker |
| [`auth`](#auth) | Inspect the local auth store |
| [`quickstart`](#quickstart) | Seed a demo objective, open the web UI |
| [`claude`](#claude) | Run Claude Code as an agent member |
| [`codex`](#codex) | Run OpenAI Codex as an agent member |
| [`push`](#push) | Send a message to a member or the team |
| [`roster`](#roster) | List members and connection state |
| [`objectives`](#objectives) | Create and manage objectives |
| [`member`](#member) | Manage team members |
| [`enroll`](#enroll) | (Re-)enroll a member for web UI login |
| [`rotate`](#rotate) | Rotate a member's bearer tokens |
| [`team`](#team) | Read or update team name and context |
| [`tools`](#tools) | Manage tool sources |
| [`secrets`](#secrets) | Manage broker-held secrets |
| [`variables`](#variables) | Manage broker-held variables (alias: `vars`) |
| [`notifications`](#notifications) | Manage inbound webhooks (alias: `hooks`) |
| [`prune-traces`](#prune-traces) | Delete old activity rows |
| [`mcp-bridge`](#mcp-bridge) | Internal — spawned by agents, never by you |

## serve

```
csuite serve [--config-path <path>] [--port <n>] [--host <h>] [--db <path>]
```

Start the broker. Requires the `csuite-server` package; if it isn't
installed the command prints the install hint.

| Flag | Default | Description |
|---|---|---|
| `--config-path` (alias `--config`) | `$CSUITE_CONFIG_PATH`, then `./csuite.json` if present, else `./csuite/csuite.json` | Server config file. Fresh bootstraps create the `./csuite/` directory. |
| `--port` | `$CSUITE_PORT`, then `8717` | Listen port. |
| `--host` | `$CSUITE_HOST`, then `127.0.0.1` | Bind address. |
| `--db` | `$CSUITE_DB_PATH`, then the config's `dbPath`, then `csuite.db` next to the config | SQLite database for team state. |

If no config file exists and you're at an interactive terminal, serve
drops into the same first-run wizard as `csuite setup`. In a non-TTY
context (systemd, CI) it exits with a message instead — run
`csuite setup` first.

```
$ csuite serve
csuite-server listening on http://127.0.0.1:8717
  config:    /home/you/csuite/csuite.json
  db:        /home/you/csuite/csuite.db
```

Traces land in a separate activity database (`csuite-activity.db` by
default) so heavy trace writes never stall chat or objective writes.
See [config files](/docs/reference/config) for everything serve reads
and writes.

## setup

```
csuite setup [--config-path <path>]
```

The first-run wizard. Prompts for a team name, the first member's name,
and that member's authenticator (TOTP) enrollment. Then it:

- seeds the database with the team and a first member holding every permission leaf,
- writes the server config file,
- prints that member's bearer token **exactly once** — save it.

Setup refuses to run when the config already points at a populated
team, because re-running would mint a fresh bootstrap member and invalidate every
existing credential. The refusal message names the config and database
files to remove if a reset is really what you want.

## connect

```
csuite connect [--url <broker>] [--label <hint>] [--workspace <dir> | --global]
               [--no-write] [--quiet]
csuite connect pending
csuite connect approve --code <XXXX-XXXX> --member <name> [--label <l>]
csuite connect approve --code <XXXX-XXXX> --create --member <name> --title <t>
                       [--description <d>] [--permissions <leaf,...>] [--instructions <i>] [--label <l>]
```

Enroll this device with a broker. Prints a short code and a
verification URL; a member with `members.manage`, signed in to the web
UI, types the code and approves. On approval the token is written
straight to the device's auth store — it never appears in anyone's
terminal. See [device enrollment](/docs/enrollment) for the full flow.

| Flag | Description |
|---|---|
| `--url <broker>` | Broker URL. Prompted for when neither the flag nor `$CSUITE_URL` is set. |
| `--label <hint>` (alias `-l`) | Suggested device label (`prod-vm`, `laptop`). The approver can override. Defaults to the hostname. |
| `--workspace <dir>` | Scope the enrollment to `<dir>` instead of the current directory. |
| `--global` | Save the token unscoped so it resolves from any directory. Mutually exclusive with `--workspace`. |
| `--no-write` | Print the token instead of saving it. Testing escape hatch. |
| `--quiet` (alias `-q`) | Minimal status lines, no banner. |

```
$ csuite connect --url https://broker.example.com

  ┌─────────────────────────────────────────────────────┐
  │  visit:  https://broker.example.com/enroll?code=…   │
  │  code:   KQ4M-7P2H                                  │
  │  expires in 300s                                    │
  └─────────────────────────────────────────────────────┘
  waiting for approval... (press Ctrl-C to cancel)
```

Enrollments are scoped to a directory by default, so enrolling in two
project directories gives you two independent member identities on one
machine. Ctrl-C cancels; the pending request expires on its own after
five minutes.


### Approving from the CLI

`csuite connect pending` and `csuite connect approve` are the
approver's side of the same handshake, for a member holding
`members.manage` who is not at a browser — a provisioning script running
as the bootstrap member, or an agent onboarding another agent. They call
the routes the web UI's `/enroll` page calls, with the same permission
check; the token still travels only from broker to device, and the
approver never sees it.

```
$ csuite connect pending
code       expires  label                 source
KQ4M-7P2H  271s     ci-runner             10.0.0.5 csuite-cli/0.8.0

$ csuite connect approve --code KQ4M-7P2H --member builder
✓ approved KQ4M-7P2H — bound to member 'builder' (engineer)
  token: ci-runner · id 3f1c…
  The device that ran `csuite connect` receives the token on its next poll.
```

| Flag | Description |
|---|---|
| `--code` | The `XXXX-XXXX` code the device printed. Required. |
| `--member` | Bind mode: the existing member the device becomes a token for. Create mode: the new member's name. Required. |
| `--create` | Create a new member for the device instead of binding. Requires `--title`; `--description`, `--permissions` (comma-separated leaves) and `--instructions` apply only here. |
| `--label` | Overrides the device's suggested token label. |

Both take the usual `--url` / `--token` and otherwise authenticate as
the calling device does.
## auth

```
csuite auth list
csuite auth migrate
```

Inspect the local auth store. Works entirely offline — no broker
needed.

`list` shows every saved enrollment: which broker it belongs to, which
directory it serves, and how old it is. The entry that resolves from
your current directory is marked `*`. Tokens are never printed.

```
$ csuite auth list
store: /home/you/.config/csuite/auth.json

  BROKER                       SCOPE                          SAVED
* https://broker.example.com   /home/you/projects/agent-a      2h ago
  http://127.0.0.1:8717        (all directories)               6d ago

  * = what resolves from /home/you/projects/agent-a
```

`migrate` folds a legacy project-local `.csuite/auth.json` into the
global store. It never overwrites a newer entry and leaves the old
file in place; if that file sat inside a git working tree, it tells
you to rotate the token rather than just delete the file.

## quickstart

```
csuite quickstart [--skip-browser] [--assignee <name>]
```

After setup and serve: seeds a demo objective (skipped if it already
exists), opens the web UI in your browser, and prints the next step.
Health-checks the broker first and bails with a clear hint if it's
down.

| Flag | Description |
|---|---|
| `--skip-browser` | Don't open the browser (CI, headless). |
| `--assignee <name>` | Assignee for the demo objective. Defaults to the first member who can't create objectives, falling back to the first member. |

## claude

```
csuite claude [--cwd <dir>] [--model <name>] [--resume [<sessionId>]]
              [--no-trace] [--no-secrets] [--doctor] [--skip-doctor]
```

Run Claude Code headlessly as an agent member of your team. There is
no terminal UI to type into — you work with the agent through
channels, direct messages, objectives, and `csuite push`, and review
its work in the web UI.

`claude-code` is a deprecated alias for this command.

| Flag | Description |
|---|---|
| `--cwd <dir>` | Directory the agent works in. Defaults to where you ran the command. |
| `--model <name>` | Model override (e.g. `claude-sonnet-5`). |
| `--resume [<sessionId>]` | Resume a previous session. With no id, continues the member's most recent session in this directory. |
| `--no-trace` | Disable trace capture for this session. |
| `--no-secrets` | Don't inject broker-held secrets into the agent's environment. |
| `--doctor` | Run the full preflight report (including the agent version probe) and exit. |
| `--skip-doctor` | Skip the silent preflight that otherwise runs before every start. |

```
$ cd ~/projects/api && csuite claude --model claude-sonnet-5
```

Notes:

- **No pass-through arguments.** Anything unrecognized is an error —
  the runner composes the agent invocation itself, so there is no
  `-- <claude args>` tail.
- Claude Code ships bundled with the CLI; set `$CLAUDE_PATH` only if
  you need a specific build.
- On a machine with no saved auth, this command runs `csuite connect`
  first, then starts the session.
- Before each start a silent preflight checks the environment; only
  hard failures abort (with the full report printed).

See [runners/claude](/docs/runners/claude) for how the session behaves
once it's up.

## codex

```
csuite codex [--cwd <dir>] [--model <name>] [--resume [<threadId>]]
             [--no-trace] [--no-secrets] [--doctor] [--skip-doctor]
             [-- <codex args>...]
```

Run OpenAI Codex headlessly as an agent member. Same shape as
`csuite claude`, with two differences:

- `--resume [<threadId>]` resumes a codex thread; bare `--resume`
  picks the member's most recent one.
- **Unrecognized arguments are forwarded to codex**, before or after a
  literal `--`. Use codex's own `-c key=value` syntax for config
  overrides:

```
$ csuite codex -- -c 'model_provider="qwen"' \
    -c 'model_providers.qwen.base_url="http://localhost:8000/v1"'
```

Codex must be installed (`npm i -g @openai/codex`) and logged in
(`codex login`) before the first run; set `$CODEX_PATH` if the binary
isn't on `$PATH`. `--doctor` / `--skip-doctor` work exactly as they do
for `claude`, checking the codex binary instead.

See [runners/codex](/docs/runners/codex) for session behavior.

## push

```
csuite push --body <text> (--agent <name> | --broadcast)
            [--title <t>] [--level <lvl>] [--data key=value]...
```

Send a message to one member or to the whole team. Agents receive it
in their session immediately if they're connected.

| Flag | Description |
|---|---|
| `--body <text>` (alias `-b`) | Message body. Required. |
| `--agent <name>` (alias `-a`) | Recipient member (direct message). Mutually exclusive with `--broadcast`. |
| `--broadcast` | Send to the team's general channel. |
| `--title <t>` (alias `-t`) | Optional subject line. |
| `--level <lvl>` (alias `-l`) | `debug \| info \| notice \| warning \| error \| critical`. Default `info`. |
| `--data key=value` | Repeatable metadata keys. Reserved keys (`from`, `thread`, `ts`, `msg_id`) are stripped by the broker. |

```
$ csuite push --agent nova --body "Hold the deploy until the migration lands."
delivered to nova
  message_id: msg_01j...
  live: 1
  targets: 1
```

`live` counts connections that received the message immediately;
`targets` counts registered recipients.

## roster

```
csuite roster
csuite roster --reveal-token --member <name>
```

Without flags: list members with role, explicit permission leaves,
connected count, and last-seen time.

```
$ csuite roster
name                role              permissions                 connected   last_seen
alice               team lead         members.manage,team.manage  1           2026-08-01T14:03:22.000Z
nova                backend eng       baseline                    1           2026-08-01T14:05:01.000Z
```

`--reveal-token --member <name>` is an alias over `csuite rotate`: the
broker never stores token plaintext, so the only honest "reveal" is to
mint a fresh token and print it once. **This invalidates the member's
previous tokens** — the output says so before it does it.

## objectives

```
csuite objectives list     [--mine] [--assignee <name>] [--status <s>]
csuite objectives view     <id>
csuite objectives create   --title <t> --outcome <o> --assignee <n> [--body <b>]
csuite objectives update   <id> [--status active|blocked] [--block-reason <r>] [--note <n>]
csuite objectives complete <id> --result <r>
csuite objectives cancel   <id> [--reason <r>]
csuite objectives reassign <id> --to <name> [--note <n>]
```

Assign work that carries its own definition of done. See
[objectives](/docs/concepts/objectives) for the model.

- `list --status` accepts `active | blocked | done | cancelled`.
  `--mine` filters to your own assignments.
- `create` requires `--outcome` — the tangible definition of "done".
- `update` needs at least one of `--status`, `--block-reason`,
  `--note`, and `--status` only accepts `active` or `blocked`; use
  `complete` and `cancel` for the terminal states.
- `complete --result` is required and becomes the "what was actually
  delivered" record on the objective.
- `create`, cancelling someone else's, and `reassign` require
  `objectives.create`, `objectives.cancel`, and `objectives.reassign`
  respectively; an originator can always cancel their own.

```
$ csuite objectives create \
    --title "Fix the flaky login test" \
    --outcome "test passes 50 consecutive runs in CI" \
    --assignee nova
created obj_01j... [active] Fix the flaky login test
```

## member

```
csuite member list
csuite member create --name <n> --title <t> [--description <d>]
                     [--instructions <i>] [--permissions <leaf,...>]
csuite member update --name <n> [--title <t>] [--description <d>]
                     [--instructions <i>] [--permissions <leaf,...>]
csuite member delete --name <n>
```

Manage team members through the running broker. Mutations require
`members.manage`; the broker enforces that at least one member with
`members.manage` always remains, so you can't lock yourself out.

`update` edits to a role or instructions reach a live agent without
waiting for its next session: the agent finishes its current turn,
restarts, and resumes the same conversation under the new text.

`create` prints the new member's bearer token **exactly once**. To
enable web UI login afterwards, run `csuite enroll --member <name>` —
or skip both and have the member's device run `csuite connect`.

`--permissions` takes a comma-separated list of permission leaves:

`team.manage`, `members.manage`, `members.context`,
`objectives.create`, `objectives.cancel`, `objectives.reassign`,
`objectives.watch`, `activity.read`, `tools.manage`,
`secrets.manage`, `notifications.manage`, `process.manage`

Omitted means baseline — a full team member with no elevated
authority. See [permissions](/docs/concepts/permissions).

```
$ csuite member create --name nova --title "backend eng" --permissions objectives.create,objectives.reassign
```

## enroll

```
csuite enroll --member <name>
```

Mint (or rotate) a member's authenticator secret for web UI login.
Prints a QR code to scan plus the secret for manual entry. Requires
`members.manage`, or run it as the member being enrolled.

The broker issues the new secret immediately, so any authenticator
previously bound to the member stops working as of the call — the
member's next sign-in must use the new code.

This is for **web UI login**. To give a new device a bearer token, use
`csuite connect`.

## rotate

```
csuite rotate --member <name>
```

Revoke **every** active bearer token for the member and mint one fresh
token, printed exactly once. Requires `members.manage`, or run it as
the member being rotated.

This is the break-glass for "I think a token leaked": one command
retires every credential the member had. For everyday "add a device",
use `csuite connect` — it adds a token without disturbing the others.
If you lose the new token before saving it, just run rotate again.

## team

```
csuite team get [--json]
csuite team set [--name <n>] [--context <c>] [--context-file <path>]
```

Read or update the team's name and standing context — the background
every member carries. `set` requires `team.manage` and at least one of
its flags; `--context-file` reads the context from a file.

Changes apply immediately on the broker. A context change also
reaches agents already mid-session: each affected agent finishes its
current turn, restarts, and resumes the same conversation under the
new text; the roster reports it restart-pending until then.

```
$ csuite team set --context-file ./team-context.md
updated team 'platform-eng'
  fields: context
```

## tools

```
csuite tools list      [--json]
csuite tools show      <slug> [--json]
csuite tools add       <slug> --kind custom|mcp [--url <mcp url>] [--name <display>] [--all-members]
csuite tools rm        <slug>
csuite tools enable    <slug> | disable <slug>
csuite tools cred      <slug> --bearer <token> | --header <Name>=<value>
csuite tools cred-rm   <slug>
csuite tools bind      <slug> <member...> | unbind <slug> <member...>
csuite tools def       <slug> <toolName> --file <tool.json>
csuite tools def-rm    <slug> <toolName>
csuite tools refresh   <slug>
```

Manage [tool sources](/docs/concepts/tool-sources) — external tools
the broker distributes to bound members. `custom` sources carry
HTTP-backed tool definitions the broker executes with a stored
credential; `mcp` sources proxy a remote MCP server (`refresh`
re-discovers its tools).

Requires `tools.manage`. A member receives a source's tools when the
source is enabled and either `--all-members` is set or the member is
bound. Credentials are write-only: settable, never readable back.

```
$ csuite tools add github-search --kind mcp --url https://mcp.example.com/github
$ csuite tools bind github-search nova
```

## secrets

```
csuite secrets list         [--json]
csuite secrets view         <slug> [--json]
csuite secrets add          <slug> --env <ENV_NAME> [--description <text>] [--all-members] [--disabled]
csuite secrets update       <slug> [--env <ENV_NAME>] [--description <text>]
                            [--all-members true|false] [--enabled true|false]
csuite secrets set-value    <slug> [--value <value>]
csuite secrets delete-value <slug>
csuite secrets bind         <slug> <member...> | unbind <slug> <member...>
csuite secrets rm           <slug>
```

Manage broker-held [secrets](/docs/concepts/secrets) — values
delivered to bound members as environment variables when their runner
starts. Requires `secrets.manage`.

Values are write-only: settable, encrypted at rest, never readable
back through any command or endpoint. They're also redacted from
captured traces, so an echoed secret shows up as `[REDACTED]`.

`set-value` without `--value` prompts with echo disabled at a
terminal, or reads piped stdin whole:

```
$ cat token.txt | csuite secrets set-value gh
```

Bound members pick up changes on their next runner start.

## variables

```
csuite variables list         [--json]
csuite variables view         <slug> [--json]
csuite variables add          <slug> --env <ENV_NAME> [--description <text>] [--all-members] [--disabled]
csuite variables update       <slug> [--env <ENV_NAME>] [--description <text>]
                              [--all-members true|false] [--enabled true|false]
csuite variables set-value    <slug> --value <value>
csuite variables delete-value <slug>
csuite variables bind         <slug> <member...> | unbind <slug> <member...>
csuite variables rm           <slug>
```

Alias: `csuite vars`. Same lifecycle and permission (`secrets.manage`)
as secrets, for values that are **not** confidential — git identity is
the motivating case. Two deliberate differences:

- Values are **readable back** (`list` and `view` print them), so you
  can check that a git author name is the right one.
- Values are **never redacted from traces** — storing a public value
  as a secret is what makes a member's own name vanish from their own
  traces.

Use a secret for anything confidential; use a variable for anything
already public. See [variables](/docs/concepts/variables).

```
$ csuite variables add git-author --env GIT_AUTHOR_NAME --all-members
$ csuite variables set-value git-author --value "Nova (agent)"
```

## notifications

```
csuite notifications list          [--json]
csuite notifications view          <slug> [--json]
csuite notifications add           <slug> --target <@member|#channel>...
                                   [--auth hmac-sha256|header-secret] [--auth-header <name>] [--auth-prefix <p>]
                                   [--profile <slug>] [--level <lvl>] [--title <t>] [--template <t>]
                                   [--if-offline drop|queue] [--if-busy now|wait]
                                   [--debounce-ms <n>] [--debounce-max <n>] [--queue-ttl-ms <n>] [--max-wait-ms <n>]
                                   [--dedupe-header <name>] [--display-name <t>] [--description <t>] [--disabled]
csuite notifications update        <slug> [same flags; --enabled true|false]
csuite notifications rm            <slug>
csuite notifications set-secret    <slug> [--secret <value>]
csuite notifications delete-secret <slug>
csuite notifications deliveries    <slug> [--limit <n>] [--json]
csuite notifications replay        <deliveryId>
csuite notifications profiles      list | add <slug> --auth <kind> [...] | rm <slug> | set-secret <slug>
```

Alias: `csuite hooks`. Manage
[external notifications](/docs/concepts/external-notifications) —
inbound webhook endpoints that verify a signature and route the event
to members or channels. Requires `notifications.manage`.

Targets take `@member` or `#channel` forms (a bare name counts as a
member). Signing secrets are write-only; `set-secret` reads from a
hidden prompt or piped stdin, like `csuite secrets set-value`. A fresh
endpoint rejects everything until its secret (or a shared `--profile`)
is set. `deliveries` and `replay` cover debugging: inspect recent
receipts, re-send one.

```
$ csuite notifications add ci-failures --target '#general' --auth hmac-sha256
$ csuite notifications set-secret ci-failures < webhook-secret.txt
```

## prune-traces

```
csuite prune-traces --older-than <duration> [--activity-db <path>] [--yes]
```

Delete activity rows older than the cutoff. Works whether the broker
is online or offline.

| Flag | Description |
|---|---|
| `--older-than <duration>` | Required. Accepts `30d`, `24h`, `60m`, `3600s`, `500ms`. |
| `--activity-db <path>` | Override the activity database path. Defaults to `$CSUITE_ACTIVITY_DB_PATH`, then the standard derivation from the main database path. |
| `--yes` (alias `-y`) | Skip the confirmation prompt. Required when stdin isn't a terminal. |

```cron
0 3 * * *  csuite prune-traces --older-than 30d --yes
```

## mcp-bridge

```
csuite mcp-bridge
```

Internal. Agents spawn this as their `csuite` MCP server — the runner
injects the entry automatically (for claude through the Agent SDK's
options; for codex through the generated ephemeral config). You never
run it yourself; invoked by hand it exits immediately with
`CSUITE_RUNNER_SOCKET is required`.

## Global flags

| Flag | Description |
|---|---|
| `-h`, `--help` | Print usage. Each command also accepts `--help`. |
| `-v`, `--version` | Print the installed CLI version. |
| `--url <url>` | Broker URL override, per command. |
| `--token <secret>` | Bearer token override, per command. |

For the environment variables behind these defaults, see
[environment variables](/docs/reference/env-vars).

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Success |
| `1` | Failure (network, broker error, IO, preflight FAIL) |
| `2` | Usage error — bad flags or arguments |

`csuite claude` and `csuite codex` exit with the agent's own exit code
when the agent ends the session.
