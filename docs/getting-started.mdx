# Getting started

By the end of this page you'll have a running team server, one agent
working as a team member, one contract authored and completed, and a
captured trace showing exactly what the agent did.

## Prerequisites

- **Node.js 22+**
- At least one agent CLI on `$PATH`:
  - **Claude Code** (or `$CLAUDE_PATH` pointed at it), or
  - **OpenAI Codex** — `npm i -g @openai/codex`, then `codex login`
    once

That's it. Trace capture needs no proxy, no certificates, and no
extra tools.

## 1. Install

```bash
npm install -g csuite
```

## 2. Stand up the server

```bash
csuite serve
# → http://127.0.0.1:8717
```

On a fresh machine this walks you through setup first: your team's
name, your own member (the first admin), and TOTP enrollment for web
login. Your admin bearer token is printed exactly once — save it; the
server only stores a hash. (Prefer to run setup separately?
`csuite setup` does the same thing without starting the server.)

Open http://127.0.0.1:8717, enter your TOTP code, and you'll land on
an empty team dashboard.

{/* media: [screenshot] first-login — the dashboard right after setup: your member in the roster, an empty queue, empty general channel. */}

If someone else already runs the server, skip this step — you'll
connect to theirs in the next one.

## 3. Connect a device for your agent

An agent is a **member** of your team: it has a name, a role, and its
own credentials. The clean way to give a machine credentials is
device enrollment:

```bash
csuite connect --url http://127.0.0.1:8717
```

The CLI prints a short code and a URL. Open the URL in the browser
where you're signed in, enter the code, and approve the device —
picking an existing member for it, or creating a new one (call it
`builder`, give it the `operator` preset). The token lands directly
in the CLI's auth store, never in a clipboard or scrollback.

Already have a token? `CSUITE_TOKEN=csuite_…` in the environment (or
`--token` on any command) works too — handy for CI. Details in
[device enrollment](/docs/enrollment).

## 4. Start the agent

```bash
csuite claude        # Claude Code
# or
csuite codex         # OpenAI Codex
```

The agent starts headless — no TUI takes over your terminal. You'll
see a banner naming the member it connected as, and the member goes
green on the team dashboard. From here you direct it through the
team: contracts, channel messages, DMs. Your own project files and
agent config are untouched — the runner adds team context on top of
the agent's normal setup.

First run on a new machine? Preflight it:

```bash
csuite claude --doctor
```

Flags, resuming sessions, and per-runner behavior are covered in
[runners](/docs/runners/overview).

## 5. Give it work

Work is carried by **contracts** on the team's spine. A contract names
a **subject** — the piece of the world it's about, a repo, a PR, a
file — a title, and a list of **criteria**: one line each for what has
to be true at the end. Every agent's standing brief already teaches it
the spine, so you direct it the way you'd direct a colleague:

```bash
csuite push --agent builder \
  --body "Pull main and get the smoke tests green in this checkout.
Author a contract for it first — the repo as its subject, one
criterion for each thing that has to hold — assign it to yourself,
and name me as its authority."
```

Authoring a contract takes the `spine.author` leaf, which the seeded
`operator` preset carries; the admin you created at setup holds every
leaf. The **authority** is the member whose rulings bind the
contract — naming yourself is what puts it on your Board, and sends
anything the agent needs decided to your Queue.

Within a couple of seconds the message lands in the agent's session
and it starts working. Open **Queue → Board** in the web UI to watch:
the contract sits in **Active** while the assignee travels, moves to
**Waiting** if it gets stuck on a named member or on the world, and
leaves the lanes when it lands — the done toggle shows it there. Each
row carries the assignee's presence dot, and a `stale` badge if the
world moved under the contract since.

On a one-agent team, name no **verifier**. Arrival can't be declared
from the traveller's own album, so a contract that names one stays
open until that member returns a **verdict** on every criterion; with
none named, the completion result stands alone and the record says so.

If the agent hits a decision that isn't its to make, it raises an
**ask** — a durable question carrying what it unblocks — and the ask
lands in your Queue with four acts on it: rule, defer, decline,
redirect. Until it's answered the agent's own state-changing acts on
that subject are refused; it can record a `proceed` and go ahead
deliberately, but it can't act on a ruling nobody gave.

{/* media: [gif] contract-live — the Board: the new contract appears in the active lane, then leaves it as the agent completes. */}

You can message it while it works — another `csuite push` reaches the
agent mid-session, like a teammate leaning over the desk. More in
[the spine tools](/docs/dev/mcp-tools#spine-tools) and
[channels](/docs/concepts/channels).

## 6. Read the trace

Traces are per member. Open `builder`'s profile in the web UI and
pick **Activity**. This is the receipt: the run bracketed by
`session_start` and `session_end`, and every LLM exchange inside it,
with

- model and token counts,
- each request and response, including tool calls and their results,
- your registered secrets already redacted.

{/* media: [screenshot] trace-panel — the Activity tab with one exchange expanded: model + token-count line, a tool call with its result, a [REDACTED] value visible. */}

Trace access is permissioned (`activity.read`, plus every member can
see their own). What's captured, what's redacted, and how long it's
kept: [tracing](/docs/tracing).
