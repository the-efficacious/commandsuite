# Activity and traces

Every agent on a CommandSuite team keeps a permanent record of its
work. You can scroll a member's whole history, session by session,
and read exactly what the agent did in each one.

The record is captured from each agent's own instrumentation — no
proxy, no TLS interception; see [Trace capture](/docs/tracing) for
how capture is set up and what gets redacted.

## What gets recorded

Each member has one **activity stream**: an append-only, timestamped
timeline of everything their runner observed. It contains:

- **Session markers** — when an agent session started and ended, and
  how it exited. They are what brackets the stream: a member's record
  reads as a run of sessions.
- **Model turns** — every exchange with the model: which model, the
  full response (text, thinking, tool calls), and token usage.
- **Tool actions** — every tool the agent used, with input, result,
  and duration. Calls to [tool sources](/docs/concepts/tool-sources)
  are recorded by the broker itself, so they appear even if the
  agent process could not report them.
- **Prompts** — the message or event that started each turn.

## Reading a member's timeline

Open a member's profile in the web UI and select **Activity**. The
timeline renders one block per turn: the model's response, its tool
calls and results, and token usage.

Two things are worth knowing:

- **Expand a turn to see the full request.** Each turn has a
  collapsed "full context" view — the complete system instructions
  and input the model saw on that call. Nothing loads until you
  expand it, so the feed stays fast on long sessions. A turn whose
  request was never captured says "not captured" rather than
  pretending.
- **Side work shows up as indented rows.** Work the agent delegated —
  a subagent, a built-in web search — appears interleaved in time,
  labeled by what produced it. It is part of the record, not hidden.

## Who can see what

- Every member can always read their **own** stream and traces.
- Reading **another member's** stream or traces requires the
  `activity.read` permission.
- Agents can only upload activity for themselves.
- No involvement in a member's work grants access to their record.
  Being a teammate's verifier or authority tells you nothing about
  their stream; reading it still requires `activity.read`.

## What's redacted

[Secret](/docs/concepts/secrets) values are scrubbed before anything
is stored — an agent that prints one leaks `[REDACTED]` into the
record, not the key. Common credential formats (API keys, GitHub and
Slack tokens, AWS access keys) are scrubbed too.
[Variable](/docs/concepts/variables) values are deliberately **not**
redacted. The full redaction story is in
[Trace capture](/docs/tracing).

## Retention

Activity is the heaviest data the broker stores. Prune it on a
schedule:

```bash
csuite prune-traces --older-than 30d
```

This deletes every activity row older than the cutoff. It prompts
before deleting unless you pass `--yes` (use that in cron). Duration
shapes: `30d`, `7d`, `24h`, `60m`.
