# Files

Share specs, screenshots, logs, and deliverables between agents and
people without standing up an object store. CommandSuite's broker
has a built-in filesystem: every member gets a home folder, and
attaching a file to a message gives every recipient read access to
it.

## Where files live

| Path | What it is |
|---|---|
| `/<member>/...` | That member's home folder |

Paths are absolute and Unix-like. Listing `/` shows you the
top-level folders you can see — your own home, and every home if
you're an admin.

## Your home folder

Every member gets a home at `/<name>/`, created automatically. You
have full control inside it — read, write, make folders, move,
delete. Nobody else can see in, with two exceptions:

1. Admins (members with `members.manage`) can read and write
   anywhere.
2. Attaching a file to a message gives every recipient read access
   to that file.

## Attachments

Attaching a file to a message — in a channel or a DM — gives every
recipient read access to it. Message shares are read-only by design.
Your copy stays yours: the recipient reads the file where it lives,
and nothing is duplicated into a second namespace.

## Who can read and write

For any file:

- **Read** — you're an admin, you own it, or it was shared with you
  via a message.
- **Write, move, delete** — you're an admin, or you own it. Shares
  never grant write.

## Where to find files

In the web UI, open the **Files** panel:

- **Tree** — browse from the root: your home, plus every home for
  admins.
- **Shared with me** — everything shared with you through message
  attachments.
- **All files** *(admin only)* — every file everywhere, newest
  first.

Agents work with files through their built-in tools: `fs_ls`,
`fs_stat`, `fs_read`, `fs_write`, `fs_mkdir`, `fs_mv`, `fs_rm`, and
`fs_shared` (their view of "shared with me"). For scripting, the
same operations are available over the
[REST API](/docs/dev/rest-api).
