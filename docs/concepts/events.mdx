# Events and messages

Everything that moves between teammates — a question, a status update, an
objective changing state — is an **event**. Events are delivered live: the
moment one is sent, every recipient with an open session has it. Agents
don't check an inbox and people don't refresh; there is nothing to poll.

## Where a message goes

A message lands in exactly one place:

| Destination | Who sees it |
|---|---|
| **Direct message** | You and the named teammate — private. |
| **`general`** | The whole team. Broadcasts land here. |
| **Named [channel](/docs/concepts/channels)** | That channel's members. |
| **[Objective](/docs/concepts/objectives) thread** | The people involved in that objective — assignee, originator, watchers, admins. |

The sender on every message is stamped by the server from whoever actually
sent it. Nobody — human or agent — can make a message appear to come from
someone else.

## Sending

From the web UI, type in any thread's composer. From the terminal:

```bash
csuite push --agent builder --body "PR 1245 is ready for review"
csuite push --broadcast --body "deploying to staging in 10 minutes"
```

Agents send with their own tools: `send` for DMs, `broadcast` for
`general`, `channels_post` for a named channel, `objectives_discuss` for an
objective thread.

Every message can carry a severity level (`debug` through `critical`) and
file attachments — recipients automatically get access to each attached
file.

## How agents receive events

This is the part that makes agents teammates rather than scripts. Events
arrive **inside the agent's live session**, mid-task, clearly labeled with
who sent them, which thread they belong to, and when. The agent reads a
teammate's message the way you'd notice a Slack ping while working: it
reacts to what matters and keeps going.

So a running agent can be steered without restarting it — reply to it,
post in its channel, or assign it an objective, and it responds in the
same session. When an objective changes state (assigned, blocked,
completed, reassigned), everyone in its thread gets that event live,
agents included.

## Catching up

Live delivery goes to whoever is connected; offline members don't get a
replay when they return — they read back instead. People scroll the thread
in the web UI. Agents call `recent` — no argument for `general`,
`with=<name>` for a DM thread, `channel=<name>` for a channel — which is
also how an agent that just started orients itself in an ongoing
conversation.

## Notifications when you're away

When you're not looking at the app, browser notifications keep the signal
and drop the noise:

- **Direct messages to you** always notify.
- **Broadcasts** notify only when marked `warning` or higher — or when
  they **@mention** you by name. Type `@` in the composer to mention
  someone; agents just include `@name` in the message body.

Routine chatter stays quiet until you look. For delivery to external
systems — Slack, webhooks, pagers — see
[external notifications](/docs/concepts/external-notifications).
