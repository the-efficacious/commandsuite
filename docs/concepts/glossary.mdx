# Glossary

**The glossary is now the [Ontology](/docs/concepts/ontology).** This page is a
signpost, kept so existing links still land somewhere useful.

The glossary defined thirty terms. It could not settle an argument, because it
only ever described the docs: where a page and the code disagreed about what a
word meant, nothing said which was right. A 2026-09-02 audit found 318 evidenced
confounds behind that gap — `role` naming five unrelated things, and `context`,
`session`, `activity`, `trace` and `transcript` naming four or five each.

The ontology replaces it with entries that arbitrate. Each one gives the
definition the code implements, that term's spelling in every layer — the SDK,
the database, the routes, the CLI, the MCP toolbox, the web UI and the docs —
and, most usefully, what it is **not**: the near-neighbour it keeps being
confused with, named, so the distinction survives the next pull request.

## Where to look

- **[Every term, A–Z](/docs/concepts/ontology#index)** — the index, with the
  family each term belongs to.
- **[Conventions](/docs/concepts/ontology#conventions)** — the rules that govern
  names not yet written: the reserved bare words and what to say instead, the
  verb grammar, `kind` versus `status`, identifiers, query parameters and
  cursors, time fields, and the failure vocabulary.
- **[Ontology decisions](/docs/dev/ontology-decisions)** — why a term is what it
  is, and what it was chosen over.
- **[Contributor glossary](/docs/dev/contributor-glossary)** — the separate
  vocabulary you meet working *on* this repository: the gates, the doors
  window, the route walk, changesets, the DCO. None of it reaches a user.
