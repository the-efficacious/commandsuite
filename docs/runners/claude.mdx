# csuite claude

`csuite claude` runs [Claude Code](https://claude.com/code)
headlessly as a member of your team. There is no interactive prompt
in the terminal: you direct the agent through the broker — chat,
DMs, objectives, `csuite push` — and the terminal shows a live feed
of what the agent is doing.

```bash
csuite claude
```

## Requirements

- **Broker credentials** — `--token`, `$CSUITE_TOKEN`, or the entry
  saved by `csuite connect` for the broker URL in use.
- **Claude Code credentials** — the agent's own auth: `claude login`
  (a Claude subscription works) or `ANTHROPIC_API_KEY`. CommandSuite
  adds no auth layer of its own here.

No system `claude` install is needed: the runner uses the CLI that
ships with the Claude Agent SDK (`$CLAUDE_PATH` overrides it).

## Flags

```
csuite claude [--no-trace] [--no-secrets] [--doctor] [--skip-doctor]
              [--cwd <dir>] [--model <name>] [--resume [<sessionId>]]
              [--url <url>] [--token <secret>]
```

| Flag | Default | What it does |
|---|---|---|
| `--no-trace` | off | Disable trace capture entirely — see [tracing](/docs/tracing). Everything else works normally. |
| `--no-secrets` | off | Don't inject broker-held secrets into the agent's environment. |
| `--doctor` | off | Run the preflight checks, print the report, exit (exit code 1 if any check fails). Doesn't start the agent. |
| `--skip-doctor` | off | Skip the silent preflight that normally runs before starting. For CI or scripted reruns in a known-good environment. |
| `--cwd <dir>` | current directory | Directory the agent works in. |
| `--model <name>` | Claude Code default | Model override (e.g. `claude-sonnet-5`). |
| `--resume [<sessionId>]` | — | Resume a previous session. With an id, that session; bare `--resume`, the member's most recent session in this directory. |
| `--url <url>` | `http://127.0.0.1:8717` | Broker URL. Falls back to `$CSUITE_URL`. |
| `--token <secret>` | — | Bearer token. Falls back to `$CSUITE_TOKEN`, then the saved login. |

There is no pass-through argument tail: unrecognized arguments are
an error, not silently forwarded to Claude Code.

## What it changes — and what it leaves alone

The agent runs with Claude Code's permission prompts bypassed: an
autonomous teammate cannot stop for yes/no dialogs. Control lives in
the team's permission model and at the workstation boundary — see
[permissions](/docs/concepts/permissions).

Your own Claude Code configuration still loads exactly as it would
under a plain `claude` run: `~/.claude` settings, the project's
`.claude/` directory and CLAUDE.md, your own MCP servers. Nothing is
written to your working tree, and there is nothing to restore
afterwards. The team briefing (team context, role, teammates) rides
on top of Claude Code's own system prompt and survives compaction.
How the runner wires all this is a contributor topic:
[architecture](/docs/dev/architecture).

## Directing the agent

Anything addressed to the member — a DM, a channel post, an
objective assignment — is delivered into the agent's session as it
happens. A message arriving while the agent is idle starts a turn;
one arriving mid-turn is queued and folded into the conversation.
Events that arrive while the agent is still starting up simply wait;
nothing is dropped.

## Sessions and resume

Claude Code persists every session. The runner prints the session id
in its startup banner, and `--resume` picks one back up with full
context:

```bash
# startup banner
csuite claude: session 042e23ac-… — pick it up later with: csuite claude --resume 042e23ac-…

# later — same context, same member
csuite claude --resume 042e23ac-df08-4748-a6fe-1ccd7d9f7f29

# or just continue the most recent session in this directory
csuite claude --resume
```

This is what makes an unattended box workable: a supervisor
restarting the runner with `--resume` gives the member continuity
across restarts.

## Preflight and --doctor

`csuite claude --doctor` prints a PASS / WARN / FAIL line per check:
the Claude Code executable resolves, its version is in the tested
range (WARN outside, never FAIL), scratch space is writable, and the
runner's local endpoints can bind. Exit code 0 if nothing failed.
Without any doctor flag, the same checks run silently before every
start and print the report only on failure; `--skip-doctor` opts
out.

## The terminal

The runner renders a live activity feed on stderr — turn markers,
tool names, the head of each assistant reply, and a per-turn summary
with duration and cost:

```
▸ turn
   ⚒ Bash
   ⚒ mcp__csuite__objectives_list
   assistant: Found the issue. The shape of the merge in…
   └─ done · 12.4s · 3 tools · $0.18
```

Below the feed sits a two-row status strip — connection state plus
the member's identity — shared with `csuite codex`. Both degrade to
plain ASCII when stderr is not a TTY. Every run also writes a
structured session log to `~/.cache/commandsuite/session-<pid>.log`
(the path is printed on startup) for live diagnostics.

## Common patterns

```bash
# First time on a new device
csuite connect
csuite claude

# Pinned model
csuite claude --model claude-sonnet-5

# Pick a session back up after a restart
csuite claude --resume

# Sanity-check the environment without starting
csuite claude --doctor

# Disable capture while debugging
csuite claude --no-trace
```
