# csuite codex

`csuite codex` runs OpenAI Codex headlessly as a member of your
team. There is no prompt in the terminal: you direct the agent
through the broker — chat, DMs, objectives, `csuite push` — and its
output flows back through the same channels. Useful for long-running
agents on a workstation, CI workers, or remote VMs where nobody is
at the keyboard.

```bash
csuite codex
```

## Requirements

- **`codex` installed** — on `$PATH`, or pointed at with
  `$CODEX_PATH`: `npm install -g @openai/codex`
- **`codex login` run once** on the machine. The runner shares the
  login, so OAuth refreshes persist.
- **Broker credentials** — `--token`, `$CSUITE_TOKEN`, or the entry
  saved by `csuite connect`.

Each run gives codex a private, disposable home. Your login and the
member's thread history are shared into it, which is what makes
`--resume` work across runs. Member-local stdio MCP servers use the
durable file described below; other settings in `~/.codex/config.toml`
are not copied. The wiring is a contributor topic — see
[architecture](/docs/dev/architecture).

## Flags

```
csuite codex [--no-trace] [--no-secrets] [--doctor] [--skip-doctor]
             [--cwd <dir>] [--model <name>] [--resume [<threadId>]]
             [--url <url>] [--token <secret>]
             [-- <codex args>...]
```

| Flag | Default | What it does |
|---|---|---|
| `--no-trace` | off | Disable trace capture entirely — see [tracing](/docs/tracing). Everything else works normally. |
| `--no-secrets` | off | Don't inject broker-held secrets into the agent's environment. |
| `--doctor` | off | Run the preflight checks, print the report, exit (exit code 1 if any check fails). Doesn't start the agent. |
| `--skip-doctor` | off | Skip the silent preflight that normally runs before starting. |
| `--cwd <dir>` | current directory | Directory codex works in — its shell and patch tools resolve paths from here. |
| `--model <name>` | codex picks | Model for the thread (e.g. `gpt-5`). Codex's own default applies when omitted. |
| `--resume [<threadId>]` | fresh thread | Resume a previous thread. With an id (printed in the startup banner of the run that created it), that thread; bare `--resume`, this member's most recent thread on this machine. |
| `--url <url>` | `http://127.0.0.1:8717` | Broker URL. Falls back to `$CSUITE_URL`. |
| `--token <secret>` | — | Bearer token. Falls back to `$CSUITE_TOKEN`, then the saved login. |
| `-- <args>` | — | Everything after `--` is forwarded verbatim to codex. |

Unlike `csuite claude`, unrecognized arguments are not an error —
they fall through to codex too, with or without the `--` separator.
Use codex's own `-c key=value` syntax to override its configuration.
Overrides cannot replace `mcp_servers.csuite`, the runner-managed
bridge; other settings remain a supported one-run escape hatch.

## Local stdio MCP servers

Tool sources are for URL-reachable servers that the broker can call.
A server running as a local process on this member's workstation instead
belongs in `~/.config/csuite/codex/mcp-servers.json` (or under
`$XDG_CONFIG_HOME`):

```json
{
  "version": 1,
  "servers": {
    "chrome-devtools": {
      "command": "npx",
      "args": ["-y", "chrome-devtools-mcp@latest"],
      "env": {},
      "cwd": "/home/agent/work",
      "enabled": true,
      "startupTimeoutSec": 20,
      "toolTimeoutSec": 60
    }
  }
}
```

The schema is strict, `cwd` must be absolute, and `csuite` is a reserved
server name. The runner reads this file for every child generation, so a
`reload`, restart, or runner cycle sees its current contents while the
runner-managed bridge always wins.

Do not use `codex mcp add` for a CommandSuite runner: it writes
`~/.codex/config.toml`, outside the disposable home the child reads. If
that file contains MCP entries, startup and `--doctor` fail loudly and
name the durable path above instead of silently discarding them.

```bash
csuite codex --doctor
```

The doctor lists the enabled local servers and their source file without
requiring a Codex model credential. The `codex` binary must still be
installed for the complete doctor report to pass. For a one-run setting,
Codex's native `-c key=value` overrides remain available; an override of
the reserved `mcp_servers.csuite` bridge is refused.

## The headless posture

Codex runs with approvals off (`approvalPolicy: never`) and the
sandbox open (`sandbox: danger-full-access`): headless means
anything that would prompt would block the run forever. The controls
live in the team's permission model and at the workstation
boundary — see [permissions](/docs/concepts/permissions). Codex's
tighter sandbox modes (`workspace-write`, `read-only`) are not
exposed as a runner flag today.

The posture is re-asserted on `--resume`, so a resumed agent comes
back exactly as headless as a fresh one.

## Directing the agent

Anything addressed to the member is delivered into codex's session
as it happens — a message arriving while codex is idle starts a
turn; one arriving mid-turn is injected into the live turn. A burst
of events (say, ten objective updates at once) is bundled into a
single delivery rather than ten interruptions. Events that arrive
while codex is still starting up wait; nothing is dropped.

The terminal shows the runner's activity feed plus the same two-row
status strip as `csuite claude` — connection state and member
identity — and a structured session log is written to
`~/.cache/commandsuite/session-<pid>.log`.

## Threads and resume

Codex threads are kept durably per member, so they survive the run:

```bash
csuite codex --resume 0197c9e1-…   # a specific thread (id from its startup banner)
csuite codex --resume              # this member's most recent thread
```

## Traces

Capture is built entirely from artifacts codex produces about its
own work — no proxy, no certificates. Reasoning appears as summaries
only: OpenAI encrypts the raw chain of thought, and it never reaches
CommandSuite. See [tracing](/docs/tracing); pipeline internals live
at [trace-pipeline](/docs/dev/trace-pipeline).

## Local and self-hosted providers

Codex supports OpenAI-compatible providers via its native
`-c key=value` overrides, which pass straight through:

```bash
# llama.cpp / llama-server on :8000
csuite codex \
  -c 'model_provider="local"' \
  -c 'model_providers.local.name="local"' \
  -c 'model_providers.local.base_url="http://localhost:8000/v1"' \
  -c 'model_providers.local.wire_api="responses"'
```

Notes that matter in practice: `--model` is a csuite flag, so it
goes before any `--` (the codex-native `-c 'model="…"'` works too).
Codex 0.120+ speaks the OpenAI Responses API exclusively — the
provider must expose `/v1/responses`, `wire_api` must be
`"responses"`, and `name` must be set explicitly (llama-server build
8826+ includes the endpoint). For providers with no API key, set
`OPENAI_API_KEY` to any non-empty string; codex checks for its
presence and local servers ignore the value.

## Common patterns

```bash
# Cold start on a new device
csuite connect
codex login            # if not already done
csuite codex

# Pin a model
csuite codex --model gpt-5

# Run against a specific working tree
csuite codex --cwd ~/projects/widget-service

# Pick the most recent thread back up
csuite codex --resume

# Disable capture while debugging
csuite codex --no-trace
```
